# YEMEN SCRIPT VIP — SHARAF

## محتويات المشروع
- `index.html`: واجهة عربية RTL، مكتبة 210 إعدادات لكل فئة (14 فئة = 2,940 إعداداً)، بحث وتصفية وتعديل وحفظ محلي.
- `server.js`: خادم Node.js وواجهات API للتحقق من الاشتراك ولوحة الإدارة.
- `package.json`: اعتماديات الخادم.

## تشغيل الواجهة كتجربة فقط
افتح `index.html` في متصفح الهاتف أو الكمبيوتر. في هذه الحالة لن يعمل تسجيل الدخول/إدارة الأكواد دون خادم. لا توجد أكواد سرية مضمنة في HTML.

## تشغيل النظام الكامل
يتطلب Node.js 18 أو أحدث:
1. ضع `index.html` داخل مجلد باسم `public`.
2. من مجلد المشروع نفّذ `npm install`.
3. أنشئ كلمة مرور قوية للمطور ثم ولّد hash لها:
   `node -e "require('bcryptjs').hash('YOUR_STRONG_PASSWORD',12).then(console.log)"`
4. شغّل الخادم مع متغيرات البيئة:
   - Linux/macOS:
     `JWT_SECRET='ضع_سراً_عشوائياً_طويلاً_هنا' ADMIN_PASSWORD_HASH='الناتج_من_bcrypt' npm start`
   - Windows PowerShell:
     `$env:JWT_SECRET='سر_عشوائي_طويل'; $env:ADMIN_PASSWORD_HASH='bcrypt_hash'; npm start`
5. افتح `http://localhost:3000`. للنشر العام استخدم HTTPS وخادماً موثوقاً، ولا تشغّل HTTP مكشوفاً على الإنترنت.

## تشغيله على Android
- للتجربة: انقل `index.html` إلى الهاتف وافتحه بمتصفح حديث.
- للخادم: يمكن تشغيل Node.js في بيئة تطوير على Android أو استضافة المشروع على خادم Node.js. الاستخدام العملي للمشتركين يتطلب نشر الخادم وربط نطاق HTTPS.
- لا تشارك `JWT_SECRET` أو كلمة مرور المطور أو قاعدة البيانات.

## نقاط أمنية
- أكواد الاشتراك لا تُخزن كنص صريح في SQLite؛ يخزن SHA-256 hash فقط، ويعرض الكود مرة واحدة عند إنشائه.
- كلمة مرور الإدارة محفوظة كـ bcrypt hash في متغير بيئة، وليس في HTML.
- حماية JWT، وتحديد معدل الطلبات، وHelmet مفعّلة. أضف نسخاً احتياطية ومراقبة وسجلات وتحققاً إضافياً قبل الاستخدام التجاري.
- زر الإيقاف يوقف الكود. الحذف النهائي غير متاح عمداً للحفاظ على سجل الاشتراكات.
- قيم الحساسية تجريبية مولّدة لأغراض التنظيم والاختبار، وليست توصيات رسمية أو مضمونة لكل جهاز. لا يتصل المشروع بملفات Free Fire ولا يعدّل اللعبة ولا ينفذ غشاً.
- المكتبة تولّد 210 صفوف منفصلة لكل فئة عند العرض؛ لا يعني ذلك أن كل قيمة اختبرت على كل موديل.
